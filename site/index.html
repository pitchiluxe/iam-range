What is inside

The tools an identity engineer uses on an ordinary day, wired to one directory so a change in one place shows up in the others.

Active Directory Users and Computers

The snap-in, backed by a real directory. Create OUs, users and groups; the tree shows what exists and nothing that does not.

PowerShell

A working subset of the AD cmdlets, plus scripts and templates for bulk work. Everything the console can do, the shell can do.

Privileged Identity Management

Eligible versus active, time-bound activation, approvals that refuse self-approval, and standing privilege you have to go and find.

Okta and Entra ID

A hybrid estate with a sync cycle that is not instant, SCIM that is switched off by default, and soft matches that fail the way real ones do.

Ticket queue

Work raised for the state your domain is actually in, with the evidence made true before the ticket describes it.

Tutor and documentation

An assistant that asks before it tells, answers from a written reference, and names the article it used so you can check it.

How it goes

The domain starts empty. Everything in it gets there because you put it there.

  1. Sign in as the administrator. The directory has one account and no structure — the same thing you would find on a freshly promoted domain controller.
  2. Build it out. The first ticket asks for an OU hierarchy, because where an account lives decides which policy and delegation reach it.
  3. Staff it. Create people, and they appear on the login screen. Sign in as one and the desktop changes: HR does not get Active Directory.
  4. Handle what goes wrong. Lockouts, leavers who still have access, standing admin rights nobody approved, two cloud identities for one person.
  5. Write it up. Incident reports, access reviews and change records, because being able to explain what you did is the part interviews test.

The optional part

Everything above works offline with nothing else installed.

The tutor and the ticket generator can run against Ollama, a local model runtime. Nothing leaves your machine — the model runs on it. Install Ollama, then ollama pull llama3.2, and the tutor composes answers instead of quoting them.

Without it the tutor quotes the documentation and tickets use their built-in wording. That is a narrower experience, not a broken one, and it is the one most people will have.
